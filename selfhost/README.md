# Goose in Goose

The compiler is written in Goose: source loading, parsing, checking, specialization, optimization, native C and direct Wasm emission, and the command-line driver. The [IR contract](IR.md) describes the stage interfaces.

## Bootstrap

From the repository root, with Python 3 and a native C compiler (Clang by default):

```sh
source build/performance-env.sh
python scripts/bootstrap.py --verify
```

The checked-in seed is C generated by the Goose compiler. Bootstrap builds the seed, uses it to compile the current Goose compiler to C, and builds that compiler. Verification requires identical consecutive self-generated C outputs. The installed compiler and standard library are in `build/bin`; `build/bootstrap/report.json` records inputs and commands. Use `--cc` to select a C compiler.

## Contracts

```sh
python tests/conformance.py --compiler build/bin/goose \
  --output-dir build/conformance --levels 0 2
```

Use a fresh output directory. The suite checks frozen sources, outputs, exit statuses and failure phases without a reference compiler or an expected-output update mode. The report records failures and input hashes. See the [guide](../docs/GUIDE.md) for build and execution commands.

Snapshot 32 passed 4,558 of 5,021 source and output contracts; 463 failed. On checks shared with snapshot 27, 198 improved and none regressed. The curated Wasm corpus passed 1,944/1,944 checks in both Wasmtime and V8. All 52 expanded native thread runtime checks passed.

Native thread and queue support, slot and span pools, and checked typed-index byte access are included in this snapshot. Packed relative cells, general variable images, and frontend lifetime and construction gaps remain; these results do not establish parity.
