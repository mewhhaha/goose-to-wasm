# Upstream feature tracker

This page tracks which [upstream Goose](https://github.com/aardappel/goose) language, library and tool features this compiler supports. Update a row in the same change that moves it. The frozen [conformance contracts](../tests/conformance/cases.json) remain the qualification gate. This page also covers upstream work that landed after those contracts were pinned.

**Inventory (2026-11-14).**
- Contracts are pinned at upstream `2e2bede`; this inventory compares against upstream HEAD `855f103` (2026-11-12), 236 commits later.
- Compiler: the sources of `27040e5` (root struct storage, `defer`, `const if`, the small-gap and named-constant fixes, stdlib abort sites and `slice_pool`'s externs, on the indexed checker of `eb0c15d`), built by `scripts/bootstrap.py --verify` at a fixed point with clang 23, `-O2` Goose and no profile. Executable SHA-256 `cffd13ea…`.
- How it was run: every upstream HEAD test, native target at `-O0`, with the HEAD standard library, 4 jobs. Positive tests compile, run and compare against `test/expected`. `errors` must fail at parse; `errors_tc` must fail at check.
- Hand verdicts: ten results are carried from the first inventory (below), each with the same first diagnostic as then. `packages/pkg_own_c` passes when its C is linked by hand, and nine `errors_tc/recovery` files count as rejected although they stop at parse.
- Not covered: `-O2`, direct Wasm, upstream's second `GS_DEBUG` run, and the JIT, LSP and Python tool tests.
- To re-run: clone upstream, then `python3 tests/upstream_inventory.py --upstream <checkout> --output-dir build/feature-inventory`. Add `--summarize` to print the totals from an earlier run.

Status key: **yes** = matches upstream on the tests named. **partial** = some forms or stages work. **refused** = parsed, then refused with a clear diagnostic at the named stage. **no** = not recognized. **wip** = a branch is in progress.

## Differences found by the upstream differential run

About 700 generated programs were checked and run with this compiler and with plain upstream `32a4f44` (`goose run`, its own stdlib). These checker disagreements are fixed. Each contract's expected output comes from that upstream build, and its rule is cited from the pinned `goose_spec.md` at `2e2bede`.

| Difference | Rule | Status | Evidence and notes |
|---|---|---|---|
| A variable-mode enum (`E..`) was assignable unless a payload field was frozen | §4.4 | yes | Upstream freezes every variable-mode ADT lvalue: a whole assignment, one through an `E..&`, and an assignment to a struct field of that type are all errors. We used to accept them. The write was dropped (`e = E.Data { 2 }` still printed `Data { 1 }`), and assigning through a reference crashed natively. An `E..` whose payload holds a resizable tail stays assignable, and so do a fixed-mode value and a payload's fixed-size field. Contracts: `corpus/contracts/upstream-differential/frozen-enum-{assign,reference,field}`, `frozen-enum-assignable/{native,wasm-direct}`. |
| A return moved a local into a named function's by-value argument | §4.1, §7.3 | yes | `return count(a)` and a final `1 + count(a)` for a non-fixed `a` are errors upstream, as the same call in a `let` always was here. The return still moves the local into the value it returns: its fields, elements and selected branches. Within the returned expression it also moves into a block's argument, even under an operand or a named function's argument (upstream accepts `return 1 + F(a)` and `twice(F(a))`). Contracts: `corpus/contracts/upstream-differential/{return-call-argument,tail-call-argument}`, `return-moves/{native,wasm-direct}`. |

| A stored array longer than a limited array's static capacity was rejected when compiled | §4.2, §9.3 | yes | Only an array or string literal must fit a static capacity when compiled. A fixed array, a larger-capacity limited array and `default<T>()` convert, and the conversion aborts at run time with "limited array capacity exceeded" at the converting line, natively and on direct Wasm. Code that never reaches the conversion is valid. Two differences remain. A call's result that overflows aborts at the caller's line here, while upstream reports the callee's `return`. Backend differences from the same run:

- Fixed: native C for a grow array of `varint` elements (`var a: varint[>..] = []; a.push(5);`) did not compile when no other image type appeared, since it wrote the element images without bringing in the image runtime. Upstream prints `[5]`; direct Wasm already did. Contracts: `corpus/contracts/upstream-differential/backends/varint-push/*`.
- Fixed: on direct Wasm, `default<S[N]>()` evaluated the element's field defaults once and copied the result, so an effectful default (`first: i64 = next()`) ran once instead of once per element. This also held nested, in a struct field array, from `..`, in a global and into a growable array. Upstream and native print `1 2 3 4 4` for the reproducer; Wasm printed `1 2 1 2 2`. A written `[v; n]` still evaluates `v` once. Contracts: `corpus/contracts/upstream-differential/backends/default-fill-effects/*`.
- Fixed: a multi-value `return 1, [f(); 4], 2` whose `f` leaves by `return … from` failed in native C with "c: expression lacks a checked type" (`return f(), [3]` aborted the compiler with index -1), because native lowered the values after the diverging one, which the checker leaves unchecked. Upstream and direct Wasm accept it. At `-O2`, with the exit function inlined, both backends also reported a missing exit target when the diverging value was not the first, since retargeting the inlined block's exits skipped a break's later values. Contracts: `corpus/contracts/upstream-differential/backends/diverging-return-value/*`.
- Open, exposed by the two native fixes above: an exit that abandons part of a destination (§7.3 **Exits**: "the exit's own value is constructed behind the abandoned part and moved down over it"). Two layers differ. (1) Mostly fixed: native C built an exit's value in the destination itself, over what the destination held, so a cancelled exit left its partial value there. After `return [11, stop()] from target`, `left` printed `[11, 2]` where the spec, upstream and direct Wasm give `[1, 2]`; a record named result kept the cancelled tag (17 where they give 1); a value the exit interrupted kept the exit's first element (`return [11, canceled(), 44]` gave `[22, 33, 44]`); and a cancelled whole assignment `a = [1, F(), 8192]` kept the old array where upstream shows the partial overwrite (`varint_grow_assignment_cancel`, also with `i64[>..]`). Native now builds each growable-array, image and enum value of a `return … from` (and of a return or break whose value can be left) behind what the destination's region holds, moves it into the destination once the exit completes, moves an image region's top back when a cancelled exit leaves its stage, and builds a whole assignment from a literal or fill in place where an exit can leave it. Programs without such exits keep the same C. Contracts: `corpus/contracts/upstream-differential/backends/abandoned-destination/*`. Still open: a cancelled whole assignment from a call (`g = make() { … }`: the `nonlocal_owned_publish_*`, `nonlocal_owned_frame_array_channel` and `nonlocal_owned_frame_tail_initialization` fixtures) keeps the old value where upstream shows the length and frame fields the call published. Some values upstream prints right after an exit come from layer 2 instead: in `nonlocal_record_forwarded` (`17 21811 68 1 7`) and `nonlocal_image_forwarded` (`3 2 7 7`) the cancelled exit's first bytes stay at the destination's start and the later exit's value lands after them, and in `nonlocal_record_interleaved` (`17 13226 34 1`) the cancelled byte stays inside the value being built; native prints what the spec gives (`51 17493 1 102 7`, `2 7 8 7`, `17 8755 1 34`). With the exit function inlined into its target (`-O1`, `-O2`), upstream and direct Wasm also build `return [11, 12], 3, [21, end()] from tuple` over the named result, printing `[11, 12] 4 [10, 20]` where upstream at `-O0` and native print `[1, 2] 4 [10, 20]`. (2) Upstream never moves a data region's top back when an exit cancels a value, and `push`, `pop` and `append` work at the top rather than at the array's length, so the abandoned bytes stay observable: after the exit above, `push(7)` prints `[1, 2, 11]` and `pop()` returns 7. The frozen direct-Wasm contracts record that behavior and the Wasm backend reproduces it. Native C will not emulate it: it contradicts the spec's moved-down value, and reproducing it would mean storing every native array at its region's top. Of the 106 `nonlocal_*` and `varint_grow_*` fixtures, whose conformance rows are direct-Wasm only, 51 now match natively, 44 differ only through layer 2, 9 through the open part of layer 1 (and layer 2), and 2 for reasons unrelated to exits (`varint_grow_narrow_append`, `nonlocal_owned_coexist_variable_enum_tails`); the 10 that read `bench_input` ran with a native stand-in for the direct-Wasm host. At `42487ee`, 45 matched, 57 differed and 4 were refused natively (2026-11-14).
