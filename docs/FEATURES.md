## Blot2 compatibility

Archived Blot2 `cb1e9e15` now compiles end-to-end through this compiler's C-host build interface (`--emit-runtime`, `--header`, `goose_init`, `goose_exit`, direct C `extern fn` linking with no `-rdynamic` or `-ldl`) into a working native `blotc-goose` release binary (`10.45 MB`, `emit` in `116.79 s`, `clang -O2` link in `134.33 s`), compiling all **18/18** `benchmarks/idiomatic/*.blot` programs to WebAssembly with **18/18** bit-exact matches against Blot2's Rust reference implementations (`16/18` at default scale; `csv_numbers` and `decimal_format` verified at `0..16` due to `cb1e9e15`'s pre-`f730b31e` linked-list `std/text.blot` builder). [C-host and native Blot2 build evidence](../bench/results/2026-11-24/blot2-chost-and-native-build/README.md)

Both frozen Blot2 snapshots (`cb1e9e15` with Blot's selected Goose standard library and `6ad5fbb` with this repository's `stdlib`) complete full reachable-program lifetime discovery and validation with **1** remaining diagnostic — the exact same site in both (`check/check.goose:3422:86` at `cb1e9e15`, `check/check.goose:3179:86` at `6ad5fbb`): `makeReflectionOrder(self_.reflections)`, which stores a slice of a grow-shrink array (`Reflection[>..<]&`) into `struct ReflectionOrder { items: Reflection[:] }`. That diagnostic is a sound §5.2 rejection where plain upstream `d5ae5bb` contains a `LoadSliceArgs` false-accept bug (`src/typecheck_calls.h:1351,1530`) that permits a direct Use-After-Free (see the lifetime table below); the end-to-end native build applies a 1-line local grow-only sort-buffer patch to `finishReflection` in its scratch archive copy only while keeping `../blot2` strictly read-only.   cd "$workload/compiler-goose/src"
```sh
  "$repo/build/dev/bin/goosew" main.goose --stdlib "$repo/stdlib" \
    --reachable-program --expansion-node-limit 1000000 --check
)
```

Backend differences from the same run:

- Fixed: native C for a grow array of `varint` elements (`var a: varint[>..] = []; a.push(5);`) did not compile when no other image type appeared, since it wrote the element images without bringing in the image runtime. Upstream prints `[5]`; direct Wasm already did. Contracts: `corpus/contracts/upstream-differential/backends/varint-push/*`.
- Fixed: on direct Wasm, `default<S[N]>()` evaluated the element's field defaults once and copied the result, so an effectful default (`first: i64 = next()`) ran once instead of once per element. This also held nested, in a struct field array, from `..`, in a global and into a growable array. Upstream and native print `1 2 3 4 4` for the reproducer; Wasm printed `1 2 1 2 2`. A written `[v; n]` still evaluates `v` once. Contracts: `corpus/contracts/upstream-differential/backends/default-fill-effects/*`.
- Fixed: a multi-value `return 1, [f(); 4], 2` whose `f` leaves by `return … from` failed in native C with "c: expression lacks a checked type" (`return f(), [3]` aborted the compiler with index -1), because native lowered the values after the diverging one, which the checker leaves unchecked. Upstream and direct Wasm accept it. At `-O2`, with the exit function inlined, both backends also reported a missing exit target when the diverging value was not the first, since retargeting the inlined block's exits skipped a break's later values. Contracts: `corpus/contracts/upstream-differential/backends/diverging-return-value/*`.
- Open, exposed by the two native fixes above: an exit that abandons part of a destination (§7.3 **Exits**: "the exit's own value is constructed behind the abandoned part and moved down over it"). Two layers differ. (1) Mostly fixed: native C built an exit's value in the destination itself, over what the destination held, so a cancelled exit left its partial value there. After `return [11, stop()] from target`, `left` printed `[11, 2]` where the spec, upstream and direct Wasm give `[1, 2]`; a record named result kept the cancelled tag (17 where they give 1); a value the exit interrupted kept the exit's first element (`return [11, canceled(), 44]` gave `[22, 33, 44]`); and a cancelled whole assignment `a = [1, F(), 8192]` kept the old array where upstream shows the partial overwrite (`varint_grow_assignment_cancel`, also with `i64[>..]`). Native now builds each growable-array, image and enum value of a `return … from` (and of a return or break whose value can be left) behind what the destination's region holds, moves it into the destination once the exit completes, moves an image region's top back when a cancelled exit leaves its stage, and builds a whole assignment from a literal or fill in place where an exit can leave it. Programs without such exits keep the same C. Contracts: `corpus/contracts/upstream-differential/backends/abandoned-destination/*`. Still open: a cancelled whole assignment from a call (`g = make() { … }`: the `nonlocal_owned_publish_*`, `nonlocal_owned_frame_array_channel` and `nonlocal_owned_frame_tail_initialization` fixtures) keeps the old value where upstream shows the length and frame fields the call published. Some values upstream prints right after an exit come from layer 2 instead: in `nonlocal_record_forwarded` (`17 21811 68 1 7`) and `nonlocal_image_forwarded` (`3 2 7 7`) the cancelled exit's first bytes stay at the destination's start and the later exit's value lands after them, and in `nonlocal_record_interleaved` (`17 13226 34 1`) the cancelled byte stays inside the value being built; native prints what the spec gives (`51 17493 1 102 7`, `2 7 8 7`, `17 8755 1 34`). Native C will not emulate it: it contradicts the spec's moved-down value, and reproducing it would mean storing every native array at its region's top.
